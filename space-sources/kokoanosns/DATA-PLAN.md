## 2026-11-08 fix: chat stuck at 「ここあが入力中…」
- User report (verbatim): `ここらてルームのチャット、ここあ入力中で止まっちゃった` — inspection evidence (b6e007e9) showed the isolated DB already held 1 user message + 1 Cocoa reply (the reply existed server-side), with no console errors: the failure was the unbounded wait, not rendering.
- **Root cause**: `sendMessage` awaited `ctx.inference.complete` with no timeout before responding, and the client had no timeout and no optimistic echo. If inference stalled or the response never landed, the send mutation stayed pending forever — typing indicator + disabled send button stuck, and the user's own bubble never appeared (messages render only from `getState`).
- **Server fix**: reply inference is raced against a 25s timeout (`REPLY_TIMEOUT_MS`); on failure / timeout / empty output, one fact-free fallback line from `FALLBACK_CHAT_REPLIES` (rotated by message id, same fallback pattern as the anniversary post) is saved as the reply, so `sendMessage` always returns with exactly one reply.
- **Client fix**: send mutation races the action against a 40s client timeout; the user's bubble is optimistically appended to the `cocoa-state` cache on mutate; on error the optimistic entry is rolled back and state is refetched (plus one delayed refetch after a timeout, since the server may still have saved the reply), and the error copy distinguishes a slow reply from a failed send.

## Long-term data behavior
- **Refresh policy**: see the 2026-11-08 section above (3 silent daily space_action schedules). Static Cocoa content (her pre-filled messages and posts) is fixed character content explicitly requested in the spec, hard-coded in the client as her authored content — it is not presented as the user's records.

- **Ordering**: talk conversation (user + Cocoa replies) interleaved chronologically after the pre-filled history; timeline feed merges Cocoa auto-posts and user posts newest-first, then the fixed static posts.
- **Time semantics**: pre-filled timestamps are relative display labels from the spec (e.g. 1時間前, talk-list time); user messages store a creation instant and render viewer-local time.
- **Read state**: `app_state` key/value row `talk_read`; first load unread badge = 2, opening the talk room calls `markRead` and the badge clears persistently.

## Rejected approaches
- **Tried**: client-only localStorage for sent messages/read state
  **Why rejected**: spec says persist in stored data if the fullstack layer allows — it does (ctx.db + actions), so use real server persistence.
- **Tried**: generated audio files for voice messages
  **Why rejected**: spec explicitly allows client-side speechSynthesis (ja-JP) reading the transcript; lighter, no audio asset pipeline, and playback is verifiable in the audit browser (button state + transcript visible even where audio output cannot be heard).
